# ACP adapter — design

**Status:** implemented and live-verified 2026-10-28 on branch `acp-claude-code`; since 2026-10-29
ADE detects and runs the user's own `claude` and sets up the bridge itself. First ACP agent: Claude
Code, through `@agentclientprotocol/claude-agent-acp`.

## Goal

Run coding agents that speak the [Agent Client Protocol](https://agentclientprotocol.com) (ACP)
inside ADE, and close the gap the README lists under limitations: _"Agent-specific interactive
approval/question protocols are not yet bridged to this UI."_ ACP makes approvals a protocol
message (`session/request_permission`), so ADE can show the agent's own question in the session
and send back the user's answer while the turn waits.

ACP was chosen over adopting Builder.io's Agent-Native framework (evaluated 2026-10-23): ACP is an
open protocol over the agent's stdio, needs no runtime dependency, and keeps ADE's rule that the
CLI owns its own credentials.

## Decisions

| Question                       | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Why                                                                                                                                                                                                                                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Library or hand-written client | Hand-written, dependency-free client in `src/local/acp.mjs`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | The client side of a turn is small: about 10 methods. ADE's agent tooling is already plain Node with no dependencies (`computer-tools-defs.mjs`).                                                                                                                                                    |
| Process lifetime               | **One agent process per turn**, like every other adapter. Each turn spawns the agent, runs `initialize`, resumes or loads the ACP session, prompts, then closes stdin, sending SIGTERM to the process group after a grace period                                                                                                                                                                                                                                                                                                                                                           | Reuses `runAgent`'s whole lifecycle unchanged: the single-turn slot, stop, steer-now, queue drain, diff refresh, failure classification, restart recovery. A long-lived process per session would need a second lifecycle.                                                                           |
| Conversation continuity        | Store the ACP `sessionId` in `session.agentSessionId`. On follow-ups, use `session/resume` if the agent advertises it, else `session/load` (ignoring the history it replays), else start fresh and say so in the session                                                                                                                                                                                                                                                                                                                                                                   | Same field Codex and OpenCode use. Agent switching already clears it.                                                                                                                                                                                                                                |
| Client capabilities            | Advertise **no** `fs` and **no** `terminal`, so the agent uses its own file and shell tools                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | ADE does not become a file server or a shell host for the agent, so the trust boundary stays where it is for every other CLI.                                                                                                                                                                        |
| Build / Plan                   | Map ADE's permission to an agent mode via `session/set_mode`: Claude Build → `acceptEdits`, Plan → `plan`. ADE also enforces Plan itself: it declines `edit`, `delete`, `move`, `execute` and `switch_mode` requests in a Plan session                                                                                                                                                                                                                                                                                                                                                     | Build matches Codex's `workspace-write`: edits apply, while shell commands and other actions ask. ADE's own check means Plan stays read-only even if an agent lacks a plan mode, or asks to leave it.                                                                                                |
| Permission requests            | Shown in the session as a card with the agent's own options (for example "Allow", "Always allow", "Reject"). The turn waits for the answer and the session shows **Needs you**. On stop or process exit, pending requests are dropped.                                                                                                                                                                                                                                                                                                                                                     | This is the gap ACP closes. ADE never invents options and never picks an `allow_*` option for the user, except for ADE's own tools (next row).                                                                                                                                                       |
| ADE's browser tools            | Passed as a stdio MCP server in `session/new` `mcpServers`. For Claude, they are pre-allowed with `_meta.claudeCode.options.allowedTools: ["mcp__ade_computer"]`                                                                                                                                                                                                                                                                                                                                                                                                                           | This mirrors Codex's `default_tools_approval_mode="approve"` for that one server. It uses a structured rule, never a match on free-text titles: Claude's title for a shell command is the command text, so title matching could be spoofed by a prompt-injected command.                             |
| Bypass mode                    | Always `allowDangerouslySkipPermissions: false` for Claude                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | ADE never offers a mode that skips all approvals.                                                                                                                                                                                                                                                    |
| Model selection                | Use the agent's `configOptions` entry with `category: "model"`. Set it with `session/set_config_option` only when the chosen id is one of its values; otherwise fail the turn as `model_not_found` and list what the agent offered. For the picker, ADE opens a session it never prompts (for Claude with `persistSession: false` and auto-memory off, so nothing is written under `~/.claude`), reads the list, and keeps it per agent and version; turns refresh it. The picker treats that list as complete: no free-text id, and a remembered id outside it falls back to the default. | ACP has no listing command, so a session is the only source of the list. ADE never guesses a list or silently ignores a model.                                                                                                                                                                       |
| Attachments                    | Images become `image` content blocks when the agent advertises `promptCapabilities.image`. Every attachment also stays in the text appendix, as for the other CLIs.                                                                                                                                                                                                                                                                                                                                                                                                                        | Same files and paths across agents.                                                                                                                                                                                                                                                                  |
| Stop reasons                   | `end_turn` → ready. `max_tokens` / `max_turn_requests` → ready, with a note that the agent stopped early. `refusal` → failed turn. `cancelled` → failed, unless it follows ADE's own decline of a mode switch in a Plan session (Claude ends that turn `cancelled` by design), which is a finished turn.                                                                                                                                                                                                                                                                                   | Turns are never reported as complete when the agent said otherwise, and Plan's normal ending is never reported as a failure.                                                                                                                                                                         |
| The plan of a Plan turn        | When ADE declines a mode switch, the plan carried in that request (`rawInput.plan`, else its text content) is shown as the agent's message.                                                                                                                                                                                                                                                                                                                                                                                                                                                | Claude puts the plan only in its ExitPlanMode request: without this, a Plan session would end with no plan on screen (found in the live check).                                                                                                                                                      |
| Agent text                     | Text runs separated by tool calls are joined with a paragraph break.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | ADE merges an agent's consecutive output into one message, and ACP streams each run without a separator.                                                                                                                                                                                             |
| Auth errors                    | ACP `-32000 Authentication required` is shown as "Authentication required: …" and classified `auth_expired`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Uses the existing recovery card and the CLI's own sign-in flow.                                                                                                                                                                                                                                      |
| What "installed" means         | Claude Code is installed when `claude` is on `PATH`, however it was installed; ADE checks its sign-in and runs it, through the bridge, with `CLAUDE_CODE_EXECUTABLE`. The bridge is ADE's plumbing: a `claude-agent-acp` on `PATH` is used as is, else ADE installs the pinned 0.99.0 once under `~/.ade/acp/claude-agent-acp-0.99.0` (with `--omit=optional`) the first time it is needed: the model list or the first task. Install in the picker installs Claude Code itself.                                                                                                           | People who use Claude Code already have it; asking them to install a bridge they have never heard of is friction, and the bridge's bundled binary would run a different Claude Code from the one in their terminal. A pinned bridge is the version ADE was tested with.                              |
| Which agents now               | **Claude Code only.** Gemini is deferred.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Gemini's permission requests have no structured tool identity, so ADE could not safely pre-allow its own browser tools there: every browser action would raise a prompt. Gemini also has no sign-in status command. The client is agent-neutral, so Gemini later is a preset plus those two answers. |

## Components

1. **`src/local/acp.mjs`**: the ACP client.
   - `createRpc`: NDJSON JSON-RPC peer.
   - `runAcpTurn(options)`: the per-turn sequence: initialize → resume, load or new → set mode → set model → prompt. It also maps `session/update` notifications to ADE callbacks, and handles `session/request_permission` with the Plan policy and a user callback. Pure, with no ADE state, and tested against a scripted fake agent.
2. **`src/local/adapters/claude.mjs`**: preset: `protocol: "acp"`, `bin: "claude"`, the pinned `bridge`, mode map, sign-in detection through `claude auth status --json`, `command({ bridge, executable })`, and `sessionMeta()` for the `_meta.claudeCode.options` above.
   **`src/local/acp-bridge.mjs`**: finds or installs the bridge. The install goes to a sibling directory that is renamed into place, so a half-finished install is never used; concurrent turns share one install, and a failed one is retried by the next turn.
3. **`runAgent` in `ade-local.mjs`**: for ACP adapters, spawn with stdin piped and hand the child to `runAcpTurn` instead of the line parser. The close handler takes the turn's exit status from the ACP outcome, because the process is ended by ADE's SIGTERM, not its own exit code. Pending permissions live on `session.pendingPermissions` and are answered by `POST /api/sessions/:id/permission` `{ requestId, optionId }`.
4. **Logs**: one compact JSON line per tool call, tool result or plan, in the vocabulary `formatLogs.mjs` already renders (`tool_call`, `tool_result`). Inputs are trimmed to short scalar fields, so file contents and diffs never fill the 500-line log.
5. **UI**:
   - `SessionView` shows a permission card for each pending request, listing the agent's options.
   - `StatusPill` gets a **Needs you** state, and the section tab counts those sessions.
   - The agent picker's "Claude Code — Coming later" row becomes a real agent.
6. **Harness** (Claude Code itself; the bridge is not a harness job):
   - Install: `npm install -g @anthropic-ai/claude-code`, offered only when `claude` is missing.
   - Update: the same command with `@latest` (Claude Code's documented npm update), offered for npm installs only. Other installs update themselves, so ADE skips the latest-version check for them (`selfUpdates`).
   - Sign-in: `claude auth login`, run in a terminal. ADE does not drive the OAuth flow, as for OpenCode and Pi.

## Error handling

- The agent exits before the prompt resolves: the turn fails, the CLI's stderr is in Logs, and pending permissions are dropped.
- The agent speaks an unsupported protocol version: the turn fails with that version named.
- An unknown agent-to-client request (for example `fs/*` despite not being advertised): answered `-32601 Method not found`.
- Notifications for another `sessionId`: ignored.
- The bridge install fails (no network, no npm): the turn fails with npm's last line and the manual `npm install -g` command; nothing half-installed is left behind.

## Testing

- **`src/local/acp.test.mjs`**: a scripted fake ACP agent covers:
  - new session and streamed text
  - resume and load (replayed history is ignored)
  - Plan mode: set_mode, and declining edit and `switch_mode` requests
  - a user-answered permission request
  - model set and model rejected (with the offered list)
  - an auth error, a crash, a protocol-version mismatch, stop reasons
- **`src/local/ade-local.acp.test.mjs`**: a full API round trip with a fake `claude-agent-acp` and a fake `claude` on `PATH`: create a session, see a pending permission, answer it over the API, reach the ready state, resume on a follow-up; the bridge receives `CLAUDE_CODE_EXECUTABLE` naming that `claude`.
- **`src/local/acp-bridge.test.mjs`**: a bridge on `PATH` is used as is; otherwise one `--omit=optional` install of the pinned version, shared by concurrent turns and reused after; a failed install leaves nothing behind and is retried.
- **Live** (real `claude-agent-acp@0.99.0` and Claude, installed to a scratch prefix; ADE state in a throwaway home):
  - `--cli auth status --json` reports the existing login, so detection needs no separate sign-in.
  - Claude listed all 29 `mcp__ade_computer` tools; `allowedTools: ["mcp__ade_computer"]` pre-approves exactly that server.
  - Build: `node -e …` raised a permission request (kind `execute`, Claude's options _Yes_ / _Yes, and don't ask again…_ / _No_). ADE paused the turn; an API answer let the command run; the turn ended ready with the output.
  - A follow-up resumed the same ACP session and Claude remembered the earlier command.
  - Plan: no file written, git clean; the plan shown as Claude's reply, the session ready.
  - The agent exits within milliseconds of ADE closing its stdin.
  - Read-only shell commands (`echo`) are auto-allowed by Claude Code itself and never reach ADE.
- **Live, own `claude`** (2026-10-29; no bridge on `PATH`, ADE state in a throwaway home):
  - Detection found the mise-installed `claude` 2.1.307 (installed, signed in, method `other`) and flagged no update.
  - The first turn installed the bridge under `~/.ade/acp` and said so in the session; `ps` showed the bridge driving the user's own `claude` binary.
  - Build permission, follow-up resume and Plan behaved as in the run above.
  - The model list came from Claude before any task (about 2 s, plus the one-time bridge install); `~/.claude/projects` gained no entry.
- **Picker** (headless Chromium, throwaway dev server): switching from Codex to Claude selects Claude's _Default_ instead of Codex's first catalog id (the previous agent's list was read during the switch), and a Codex id remembered for Claude is replaced by _Default_.
- **UI** (headless Chrome against a second dev server with the fake agent): the card renders with the agent's options, the header reads **Needs you**, and clicking _Allow_ clears the card and finishes the turn.

## Out of scope (later)

- Gemini CLI and other ACP agents (see the last decision row).
- `session/cancel` before SIGTERM on stop.
- Advertising `fs` so ADE can show the agent's edits as they happen.
- ACP elicitation (Claude's `AskUserQuestion`), which stays disabled because ADE does not advertise form elicitation.
- Effort and fast-mode config options.
- Bridging OpenCode's own permission prompts through `opencode acp`.
