# Agent Computer — design

**Status:** implemented and live-verified (Codex and OpenCode real turns on Windows; Pi extension live-tested from WSL against a Windows ADE). Updated from the original approved direction (user: "replace all the preview/port/script stuff with an agent computer the agent controls"; "keep it on our machine and free") after the first Debian+apt image proved unbuildable on the user's network.

## Goal

Replace the right-pane **Preview** (iframe + "Start development server" + attach-a-port form + Processes list) with an **Agent Computer**: a per-project, isolated Linux desktop that the coding agent drives itself (screenshots, mouse, keyboard, browser) to view and manually test the project, while the user watches live and can take the wheel. Modeled on Cursor Cloud Agents / Grok computer use, but local and free.

## Decisions

| Question                                           | Decision                                                                                                                                                   | Why                                                                                                                                                                                |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Where the computer runs                            | Local Docker container (Docker Desktop / any Docker engine ≥ 20.10)                                                                                        | Free, private, matches ADE's self-hosted principle. No E2B/cloud dependency.                                                                                                       |
| Base image                                         | `selenium/standalone-chromium` (pinned by digest) — Chromium, Xvfb, fluxbox, x11vnc, noVNC already inside; **no `apt` in the build**                        | Debian mirrors ran at 0.3–0.9 MB/s on the user's network (40+ min builds); Docker Hub pulls 1 GB in ~51 s. Build is ~6 s after the one-time base pull.                             |
| Input/screen control inside the container          | Pure Python stdlib + `ctypes` on libX11/libXtst: XTest for mouse/keys (shifted symbols handled; unmapped chars remap a spare keycode), `XGetImage` → PNG via `zlib` | No xdotool/ImageMagick packages to install; keeps the image build package-free.                                                                                                    |
| Granularity                                        | One computer per **project**                                                                                                                               | The right pane is project-scoped and ADE allows one running task per project; sessions share it.                                                                                   |
| Where the dev server runs                          | Still on the host, via ADE's existing dev-server engine (host `node_modules`, fast watching)                                                              | The _UI_ for it is removed; the _agent_ drives it through `dev_server_start/stop/status` tools.                                                                                    |
| How the container's browser reaches the dev server | Every container starts with `--add-host host.docker.internal:host-gateway`; a Python socket relay binds `127.0.0.1:PORT` inside and pumps to the host, preserving the `localhost` Host header | Works on Docker Desktop (Windows/macOS) *and* Docker Engine on Linux/WSL; Vite/Next host checks pass. Live-verified from a Windows host; WSL mirrored networking verified earlier. |
| How agents get the tools                           | One shared toolset. Codex: stdio **MCP server** (`src/local/computer-mcp.mjs`, entry; logic in `computer-tools-defs.mjs` — shebang-free so Vite SSR can import it) via `-c mcp_servers.ade_computer.*` with `default_tools_approval_mode="approve"`. OpenCode: `OPENCODE_CONFIG_CONTENT`. Pi: `-e src/local/computer-pi-extension.mjs` + tool names in `--tools` | MCP servers run outside Codex's `workspace-write` sandbox, and `approve` mode defeats its `never` approval policy that would otherwise deny MCP calls. All three CLIs call the same ADE endpoints. |
| Human view                                         | noVNC iframe (view-only by default, "Take control" toggle)                                                                                                 | Standard, no extra deps in ADE.                                                                                                                                                    |
| Windows process launching                          | `src/local/spawn.mjs` (`spawnCommand` via cross-spawn; `killTree` via `taskkill /T /F`) for every ADE-spawned binary; `stopChild` uses `killTree` first       | npm `.cmd` shims can't be spawned directly (ENOENT/EINVAL); killing only the shim orphans the real dev server holding the port.                                                    |
| Desktop appearance                                 | fluxbox with no toolbar and a plain solid background (`fbsetroot` after fluxbox startup)                                                                     | The fullscreen browser is what the agent/user need; the stock Selenium wallpaper is noise in screenshots.                                                                           |

## Components

1. **Image** `docker/agent-computer/` — `Dockerfile` (FROM `selenium/standalone-chromium@sha256:08fd2936…`), `start.sh` (Xvfb 1280×800, fluxbox, x11vnc + websockify/noVNC, plain background, Chromium fullscreen), `computer-server.py` (control API). Non-root (`seluser`). Tagged by a hash of the three files; ADE rebuilds automatically when they change.
2. **Control server (in container)** — token-protected HTTP (`X-ADE-Token`): `GET /health`, `POST /action` with `{action: screenshot|click|double_click|move|drag|type|key|scroll|open_url|wait}`. `open_url` auto-creates the localhost forward for `localhost`/`127.0.0.1` URLs and starts/raises Chromium if needed.
3. **Lifecycle (`src/local/computer.mjs`)** — `status/start/stop/action`. Containers are labelled (`ade.computer=1`, `ade.project=<id>`) and carry their VNC password + control token as labels, so ADE reconciles after a restart without persisting secrets in `workspace.json`. Ports published on `127.0.0.1` only. `--cap-drop ALL`, `no-new-privileges`, 2 CPU / 2 GB RAM / 1 GB shm.
4. **API (`ade-local.mjs`)** — `GET /api/projects/:id/computer`, `POST …/computer/start`, `POST …/computer/stop`, `POST …/computer/action`. Loopback rules unchanged. Bootstrap includes computer status per project.
5. **Tools (shared by all agents)** — `computer_screenshot`, `computer_open_url`, `computer_click`, `computer_double_click`, `computer_move`, `computer_drag`, `computer_type`, `computer_key`, `computer_scroll`, `computer_wait`, `dev_server_status`, `dev_server_start`, `dev_server_stop`. Every action tool returns a fresh screenshot so the model sees the result. Auto-starts the computer on first use. Right-click is `computer_click` with `button: "right"`.
6. **Manifest/prompt** — an `agentComputer` section (real ADE base URL captured from loopback requests, screen size, tool list, verify-visually rules). The old `devControl` curl bridge and skill file are gone.
7. **UI** — Right tab renamed **Computer**. `AgentComputerPane` shows: Docker unavailable / stopped (Start computer) / building / running (live noVNC + View only ↔ Take control + Stop). `PreviewPane`, `ProcessPanel`, port attach, and dev-script controls are removed from the UI. `/processes` and old `?pane=preview` links redirect to the Computer tab.

## Error handling

- Docker missing or daemon down → status `unavailable` with the real `docker` error; tools return that text to the agent (never pretend).
- Image build failure → status `error` with the build log tail.
- Dev server unreachable from the container → `open_url` raises with "Nothing is reachable on the host at port N. Start the project's dev server (dev_server_start)…"; the agent is told exactly that.
- Container died → status recomputed from `docker inspect` on every status call.
- ADE's URL unknown (no loopback request yet) → tools omitted for the turn and the manifest says the computer could not be connected, instead of guessing an address.

## Testing

- Unit (`node --test`): container arg/label construction, loopback-only ports, status parsing, lifecycle against fake docker, MCP JSON-RPC handshake + tools/list + tools/call against a fake ADE API, per-CLI command/env injection, Windows shim spawning and tree-kill. Tool definitions live in a shebang-free module so Vite SSR can import them (a shebang broke SSR — found live).
- Live (all done): image builds ~6 s; computer boots in 2–4 s; screenshot/click/type verified; host dev server reachable from the container's browser with `localhost` Host header; real Codex turn on Windows: `dev_server_start` → `computer_open_url` → 3 clicks → correct visual report; real OpenCode turn: all tools executed (its default model could not read images — tool layer fine); Pi in WSL loaded the extension and completed a `computer_screenshot` turn against a Windows ADE.

## Out of scope (later)

Screen recording attached to results; running the agent CLI itself inside the container; a cloud provider (E2B) behind the same interface; remote (LAN/Tailscale) viewing of the VNC stream through ADE's proxy; picking a vision-capable model automatically for OpenCode sessions.
