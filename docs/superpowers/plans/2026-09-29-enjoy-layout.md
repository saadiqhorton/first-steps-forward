# Enjoy-style layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restructure ADE's UI into Enjoy's layout (project tabs, Conversations / Files / Workflows, conversation list + thread + composer with a multi-column agent picker, Activity pane) and add harness install/update, per-turn effort/speed/permission options, a Files section and prompt workflows.

**Architecture:** TanStack Start file routes under `/p/$projectId/...` own navigation; `Shell.tsx` becomes a top bar + section tabs + resizable main/right layout. The existing Node local service (`src/local/ade-local.mjs`) gains small, separately tested modules (`capabilities.mjs`, `harness.mjs`, `workflows.mjs`, `editor.mjs#listDocuments`) that are wired into its router in one task.

**Tech Stack:** React 19, TanStack Router/Start, Tailwind v4 (existing tokens in `src/styles.css`), react-resizable-panels, Node `node:test`.

**Spec:** `docs/superpowers/specs/2026-09-29-enjoy-layout-design.md`
**CLI facts (authoritative for every flag/command):** `docs/superpowers/research/2026-09-29-cli-harness-facts.md`

## Global Constraints

- Keep ADE's current palette, fonts, utilities (`card-panel`, `label-mono`, `btn-amber`, `btn-quiet`, `btn-ink-ghost`) and components (`StatusPill`, `DiffView`, `ChecksList`, `SessionMessage`, `ModelPicker` internals). Change styling only where the new layout requires it. No dark theme.
- Work happens on `main`. **Implementer subagents never run `git commit`, `git add`, `git stash`, `git checkout` or `git reset`; the controller commits each task after review.** Never push.
- Implementers do not edit `package.json`; run new test files directly with `node --test <file>`. The controller adds them to the `test` script.
- Only touch the files listed in your task. Other tasks may be editing other files in the same working tree at the same time.
- All commands spawned with argument arrays (no shell). Never invent a CLI flag; use only flags recorded in the CLI facts file or the CLI's own `--help`.
- Existing safety guards stay: loopback/token checks, dirty-tree baseline, one running task per project, no OpenCode `--auto`, no Codex sandbox bypass flags.
- After each task: `npm run typecheck`, `npm run lint`, `npm test` pass (and `npm run build` for UI tasks). `src/routeTree.gen.ts` is regenerated by the router plugin during `npm run build`/`vite dev`; commit the regenerated file.
- Existing copy about limitations (failure kinds, dirty tree, model-swap semantics, sign-in limitations) is preserved verbatim where it moves.
