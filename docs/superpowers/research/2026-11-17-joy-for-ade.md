# ADE Workspace Assistant — JOY parity specification

**Target as of November 17, 2026.** A solo developer who uses JOY to oversee their own projects should be able to do the same work in ADE. This includes the seven advertised features and the assistant behaviors in Enjoy’s operating manual, scoped to one local ADE owner and that owner’s registered projects and installed agents. All capabilities below are release requirements within that scope. The milestones give their build order. **Workspace Assistant** is a working name.

GPT-6 Luna reviewed the public documentation. The feature page describes a combined start screen. The November 16 manual puts the live queue in Inbox and opens JOY to a conversation. ADE will offer both entry points. Its workspace overview will retain frequent workflows, projects and recent assistant chats. ADE’s existing token-gated remote client remains available to the same owner. Team accounts, memberships, invitations, roles and separate device identities are outside this scope, as are Enjoy’s subscription, branding and wider product catalog. [JOY features](https://enjoy.dev/features/#joy) · [JOY operating manual](https://enjoy.dev/help/getting-started/ask-joy/) · [Inbox](https://enjoy.dev/help/conversations/use-your-inbox/)

## Deliberately excluded

Two areas from the comparison were removed after review rather than shipped: generated themes, layouts and living backgrounds, and the bundled product-help guide. For a single developer they added surface area and maintenance without helping the daily loop of deciding, starting and reviewing work. Luna does not recreate them.

## The seven core journeys

Each row describes an acceptance scenario to run against a real ADE workspace.

| Journey | ADE behavior required for parity | How to verify it |
| --- | --- | --- |
| Open the workspace | From every project, open a home with a composer, live decisions and running work, recent assistant chats, frequent workflows and registered projects. A dedicated Inbox stays beside the selected session on a wide screen. A phone keeps the list position on Back. | Open a pending dev-command request in project B while working in A. Resolve it in B. Its inbox count updates without refresh. Closing the assistant takes you back to the prior context. |
| Catch up | Answer questions about what changed across projects or since a named time. Quote pending questions and link directly to each decision, reply or check. Read the latest thread when asked how something is going. | Seed one completed task, one failed check in a ready session, one interruption and one pending approval. The answer identifies all four outcomes accurately. Reading status consumes no turn in the destination. |
| Start work anywhere | Given an unambiguous project and task, actually start a project conversation and return its link. Use the destination’s last valid agent settings unless the user overrides them. Offer a choice for ambiguous projects. | Ask from project A to start work in B. Observe exactly one turn in B and follow its link. Repeat with an unavailable model and see the actual failure. |
| Tidy up | Identify finished sessions, complete them across projects on request, list what changed with links, and reopen named sessions. Recheck pending questions, check results and session state when committing the operation. | Tidy two projects while one candidate acquires a pending approval. The approval survives. Open the list of completed sessions, reopen one, and see both lists update. |
| Run frequent workflows | Give a single-action launch for each frequent workflow and its destination. Count successful user-initiated starts. Present a project choice when the destination is ambiguous. | Launch a workflow twice in A, open and cancel its composer in B, then use the shortcut. A gets exactly one new session with that workflow. For a predictable initial ranking, ADE will show up to four project/workflow pairs with at least two manual starts in the past 30 days. |
| Find and add projects | From the assistant, discover existing folders, show recognizable paths, register and pin the chosen projects, or create a new project and start work there. Offer discovery, creation and plain chat on a fresh install. | Discover two same-named repositories under different parents, choose one, and repeat discovery. The correct canonical folder gets one project entry. Cancelling leaves both folders alone. |
| Coordinate across projects | Let both the workspace assistant and a project agent create a child conversation or message an existing one in another registered project. Give both ends attribution, a link, delivery state and the matching answer. | Ask Web to check an API change while Web has an active turn. Its reply comes back to the origin without reopening Web. Stopping the target yields an interrupted result. Retrying delivery cannot create duplicate work. |

For example, selecting an API diff and asking “Have Web check whether its login form still works with this change” should create a normal Web task. The sender sees which revision or captured hunk was sent. The eventual reply links to Web’s recorded check result. If Web could never start its preview, the returned answer says so. Evidence capture is an ADE design choice that makes a cross-project handoff easier to verify later.

## Companion behaviors required for parity

| Area | Product behavior and release check |
| --- | --- |
| Assistant entry and history | Open from a global button or Cmd/Ctrl+J, start a new chat, return to older chats by date or full-text search, collapse the history column with Cmd/Ctrl+backslash, and preserve the open thread across navigation. Show recent reply text, unread, needs input, thinking and failed. Support mark read/unread, stop and confirmed single or batch delete. Deleting the active thread opens a fresh one. On first use, show where to return after entering a project. Assistant history belongs to the host workspace. |
| Agent, attachments and activity | Pick an installed agent and supported model/effort. Start with its saved assistant default or a supported low effort. Record the actual agent/model on replies. Paste, drop or choose a screenshot or file. Open activity during the turn and identify the current operation, retry or wait when reported. Closing the panel keeps the turn alive. Stop ends it. A global indicator shows background activity or an unseen reply. |
| Inbox | Group pinned items, pending decisions, failures, unread replies, active/queued work and ready sessions. Support project/status filters, search including completed and snoozed sessions, ordered pins and bulk actions. Keep a just-read row stable while selected. A completed thread with an unread reply is still discoverable. Show totals and a way to see more for large projects. On phones provide touch actions and one-pane navigation. Include the cross-project scheduled-workflow view on desktop if necessary by adding the underlying schedule/run data as a dependency. |
| Snooze and restore | Support presets, a specific local date/time and “when work finishes.” Show the resolved wake time, allow undo/change/early return, and expose a searchable snoozed list. Suppress its routine badges and sounds while the agent continues. Wake on expiry, turn completion for an until-finished snooze, a new user message, or an agent decision. | Read versus ask | “How is Web doing?” reads the thread. “Ask Web how it’s going” delivers a message. Forward instructions on request and label their origin in the target. Support up to five destinations per assistant reply, with independent outcomes. Requests to a more privileged target show the recipient, permission level and editable draft. The owner can send, edit or decline. Pending project questions keep their original answer controls. |
| Project agent handoffs | Child sessions inherit a permission ceiling from the initiator. Apply the cross-project send checks to project-originated messages as well. When a chain reaches 20 messages since the user last wrote, require the user to continue it. Link delivered replies in both directions and return individual failures if one target disappears. |
| Project instructions | Read the current ADE-managed project instructions, apply the requested change while preserving other text, and detect conflicting edits by revision. Show the result in project settings. All agents, including resumed sessions, receive the new revision on their next turn. Verify with two adapters and with existing repository instruction files. |
| Project identity | Set a project color, create a simple icon from a description, or use a selected existing project image. Update navigation, inbox and project settings together. Verify across reload and with two projects of the same name. |
| Voice and feedback | Speak a short cue for a reply on supported desktop clients, honor mute, chime during dictation, and expose a manual cue from the assistant control. Thinking, speaking, awaiting input and failure also have visible states. Test with sound disabled and with a phone where spoken replies are suppressed. |
| Remote owner access | The host owns assistant history, settings and execution. The existing token-gated remote client can read the same thread, send work and receive its result. Enforce ADE’s existing owner authentication for remote requests, including through a proxy. Cross-agent permission escalation remains subject to the host’s existing approval controls. |

### Handoff lifecycle

1. Resolve the request to stable project and session IDs. If two targets match, ask once with both project names and paths. Validate the local owner, target, agent and permission ceiling. If permission modes across two adapters cannot be ordered, show the editable escalation draft.
2. Reserve a durable delivery key per source turn and destination. Attach that same key to the destination message or new session under the workspace write lock. When a busy target accepts a queued follow-up, preserve the pending question and tie the future turn to the queued message.
3. Report a distinct state for approval pending, queued, delivered, replied, declined, interrupted or missing target. The answer must come from the turn that consumed that message. A pre-existing turn finishing in the same session cannot satisfy the handoff.
4. On restart or reconnect, reconcile by delivery key and target turn before retrying. If the process died after launching an agent and the outcome is uncertain, expose the interruption and its evidence. A deliberate user retry gets a fresh attempt linked to the first. Deleting an assistant chat leaves delivered project work intact and cancels its unsent drafts.

## Build sequence and release decision

1. **Workspace and Inbox.** Deliver the global routes, real status groups, search, read state, pins and direct links. Exercise an empty workspace, two busy projects and a project large enough to paginate.
2. **Assistant conversations.** Deliver the host-backed runtime, per-adapter capability checks, history, model controls, attachments, activity, stop, documentation answers and source-linked catch-up. Verify cancellation and recovery with a real CLI.
3. **Work across projects.** Deliver direct dispatch, follow-ups with returned answers, approval drafts and project-to-project tools. Exercise concurrent turns, multiple targets, deleted targets, permission differences and restart during delivery.
4. **Organize the workspace.** Deliver workflows, project discovery, project instructions, complete/reopen, snooze and project identity. Test migration against a pre-feature workspace and a second ADE process sharing the same store.
5. **Appearance and remote access.** Deliver generated themes, layouts, animated backgrounds and spoken cues. Exercise the host desktop and ADE’s existing token-authenticated remote web client, including iPhone Safari. Confirm remote owner actions retain the same host approval controls.

**Release criterion.** Record pass, failure or unsupported for every journey and companion behavior above, with the agent, client and ADE build used. A visible control, a prefilled composer or a mock reply counts only as UI evidence. Parity requires the corresponding host action, persisted result and user-visible outcome. Provider-specific gaps stay visible in the release matrix until an adapter implements them. The current deliverable is the specification.
