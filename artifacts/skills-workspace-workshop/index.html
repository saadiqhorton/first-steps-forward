How should the Skills workspace hold packaged skills?

ADE gets a fourth project section, Skills, beside Conversations, Files, and Workflows. It has to carry the Agent Skills format as it is written down: a skill folder with a SKILL.md whose frontmatter holds a name and a description, and optionally scripts/, references/, assets/ and more. A skill can be just a name and a description, or a package that carries extra folders — and every one of those files has to be editable in place, not just listed. You can import a .skill file, import a .zip that holds several skills, or write one in place. Each option below is a different answer to where that content lives and how you edit it, using the same sample library and the same import.

Same in every option

Project first-steps-forward. ADE owns two folders — .ade/skills in the project and ~/.ade/skills on the machine — so it never depends on another client. Skills found in .agents/skills or .claude/skills stay out of the way until you ask for them, and an import can hand over a .skill package, a zip with three skills, or a file that is not a skill.

What varies

The shape of the workspace: gallery, explorer split, table, import console, or a single-skill studio — and how much room each one gives to bundled files.

Mock only

Sample data only. Nothing is written to disk, no agent is called, and no account is touched. Imports land in the preview only.

Recommendation

Option 1, Gallery + drawer — chosen, and now built. It is the closest to the Workflows section that already exists, so the Skills tab reads as part of ADE rather than a new app. Cards show the one thing that varies between skills — whether the package carries extra folders — and the drawer keeps the full file list and the SKILL.md body out of the way until you ask for them. It grew two things during the workshop: a files view where every reference, script and asset is edited in place, and ADE's own folders (.ade/skills in the project, ~/.ade/skills on the machine) so the workspace never depends on .agents or .claude. Skills found in those folders are read-only until they are copied in. Option 4's per-skill import review is the next thing worth borrowing if packaged skills turn out to be the common case.
