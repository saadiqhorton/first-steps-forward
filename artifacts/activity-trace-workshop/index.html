Activity pane: Logs

Four directions for the Logs section of the right-hand Activity pane. Every option renders the same session (three turns, 30 rows run through ADE's own formatter), so what differs is layout and motion, not content. Everything inside a framed pane is a mock: its buttons do nothing and nothing here touches the network.

What is wrong today

  • Routine events take whole rows and say nothing a person can act on: “Session started”, “Turn started”, “Turn completed”, “Step started”, and unknown events like “auto retry end”.
  • Every tool call is followed by a separate “Tool finished” row, so one action costs two rows.
  • Text glyphs (▸ and ⚠) stand in for icons.
  • Every turn lands in one long scroll.

The chat already shows a one-line live status (“Reading the project”). Wording here stays plain: no tool names, no JSON.

How to read the previews

  • Live streams the run in and holds on the last step. Complete shows the finished run. Error is the same run where the last file read fails.
  • Replay plays the arrival again; Pause and speed change only that option; Reset stops everything and shows the finished run with every disclosure back at its default.
  • Theme and Reduce motion apply to every mock. Your system's reduce-motion setting is honoured automatically.

Questions to settle

  1. Should routine events be hidden everywhere? Only Ledger keeps a “show them” escape hatch.
  2. Should a failed step always force its turn open, as options 2 and 4 do here?
  3. Folding a result into its tool row needs the tool call id, which formatSessionLogs drops today. In this log a find and a read overlap and the read result arrives first, so pairing by position would attach results to the wrong rows.

Assumptions baked into every mock

  • Tool names become plain verbs: edit → Edited, read → Read, find → Looked for, bash → Ran, dev_server_status → Checked the preview.
  • The +N/−N counts come from the edit result's details.diff in the raw log; the formatter does not expose them yet.
  • Result text is trimmed to a plain phrase (“Replaced 2 blocks”) instead of the agent-facing message.
  • Reads show no result line; their content is noise to a person.
