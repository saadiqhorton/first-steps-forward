Processes

Four directions for the screen that keeps track of what an agent left running: a dev server, a watcher, a long job. Same sample project, same controls, same behaviour — only the shape, the hierarchy and the interaction change.

Source: Enjoy's Previews & processes manual Target: ADE project workspace Sample data only

What Enjoy does

  • Processes sit in the project's tab row, second to last, with a count.
  • The list groups rows under the conversation that started them.
  • Rows show a name and a status dot; a web server also shows its address and Open.
  • Selecting one opens details and its output beside the list, never over it.
  • Statuses: Running, Stop requested…, Couldn't stop, Needs checking.

What carries over

  • Search across names, conversations and details.
  • Output follows the newest line until you scroll up; Follow latest catches up.
  • Wrap lines, copy address, open in the agent browser.
  • Stop one process, or Stop all processes after a confirmation.
  • Processes disappear when they exit; nothing running says so.

What ADE can honestly show

  • ADE owns one dev server per project today, plus any approved command.
  • Owner, folder, command and address come from the real process record.
  • No invented agents, ports, usage or background jobs in the mock.
  • Every control below is a local simulation and never starts or stops a real server.
Chosen

Option 2, Rail. Processes becomes a tab in the right pane, beside Activity, Diff, Browser and Terminal. It keeps the conversation and its preview in view, expands a row for its log, and has Follow latest when you scroll back. A Processes tab beside Skills is the home for ADE itself in every project; the right-pane tab keeps the agent processes.
