Customize ADE

Four directions for a new page, /workspace/customize, where you describe a feature or behavior change and an agent builds it in a private copy of ADE. You try it, then keep it or undo it. Same sample change, same controls, same behavior; only the shape and the hierarchy change.

Page: Workspace / customize Top bar: after Luna Sample data only

What the page must do

  • Take a plain description of a feature, tool or behavior change.
  • Show the agent building it, then five checks: Typecheck, Lint, Build, Tests, Design files untouched.
  • Try it in a preview, then Keep it (only when every check passes) or Undo.
  • Keeping waits for running agents, backs up the workspace, restarts ADE and reconnects.
  • List Your changes with Remove. Mention ade --stock once.
  • One-time setup on first visit (about 0.7 GB, a few minutes) and a clear update decision.

What stays fixed

  • Design is locked. Colors, type, layout and theme can't be changed here. Functionality only, and a check enforces it.
  • The live ADE is never edited. The agent works in a private copy; the preview is a second ADE on 127.0.0.1:3101 with test data.
  • People never see git, branches, ports as settings, or builds as concepts beyond these plain words.
  • On an ADE update the changes re-apply by themselves. If one can't, the user chooses: Let the agent try again, Update without it, or Stay on 0.1.15.

What's mock

  • Every control is a local simulation with timers. Nothing builds, restarts, downloads or reaches the network.
  • The preview, the checks and the restart are drawn, not run.
  • Sample data is the same in all four: one kept change (Stop dev servers idle for 1 hour), one in progress (Copy full log button).
  • Chrome follows ADE's tokens and the Luna, Inbox, Settings and project-shell screenshots.
Recommendation

Start with Option 1, Conversation, with Option 3's calm list of changes as its Your changes sheet. The page then reads exactly like Luna: describe, watch, try, keep. The list is where Option 3 is strongest, and a sheet gives it room for status pills and Remove without a second page. Building the four showed one adjustment: the in-thread change card needs the status pill and a one-line why Keep it is off, or a failed check reads as a dead end. Option 2 earns its weight only if people run several changes at once; Option 4 is the right first-run tour and could be the one-time setup.
